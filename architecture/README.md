# Архитектурные диаграммы

| Файл | Читатель | Вопрос |
|---|---|---|
| `c4/context.mmd` | Заказчик/новый участник | Кто пользуется системой и с чем она связана? |
| `c4/container.mmd` | Разработчик/эксплуатация | Какие запускаемые части и хранилища есть? |
| `sequence/create-exchange.mmd` | Разработчик | Как проходит обмен, включая отказы? |
| `data/model.mmd` | Разработчик БД | Какие сущности, ключи и связи? |

Диаграммы Mermaid хранятся как текст и обновляются вместе с изменениями требований и архитектуры. Они описывают целевую модель, а не факт реализации.

## Соглашение об оформлении C4 в Mermaid

- Диаграммы контекста и контейнеров строятся через `flowchart`.
- Граница SkillSwap обозначается `subgraph`.
- В подписи контейнера указываются название, тип, технология с версией, ответственность и учебная работа, в которой планируется его появление.
- Подписи связей указывают направление, протокол и назначение.
- Внешние системы находятся вне `subgraph` SkillSwap.
- C4-контейнер означает отдельно запускаемую часть или хранилище данных, а не Docker-контейнер.

## Проверки согласованности (пять обязательных сверок)

| № | Сверка | Результат текущего документального прохода | Что ещё подтвердить |
|---:|---|---|---|
| 1 | Контекст ↔ контейнеры | Пользователи, модератор, почтовый провайдер, видеосвязь, GitHub Actions и проверка доступности отражены на обеих диаграммах. | Команда подтверждает, что внешние связи соответствуют принятому сценарию эксплуатации. |
| 2 | Контейнеры ↔ последовательность | Участники последовательности — браузерный клиент, REST API и PostgreSQL; все присутствуют на C4 Container. | Проверить на ревью, что не требуется отдельная ветвь загрузки статических файлов. |
| 3 | Последовательность ↔ критерии приёмки | Показаны принятие/отклонение, конфликт устаревшего статуса и двухстороннее подтверждение. | Сверить идентификаторы и полноту всех ветвей с актуальными критериями в `requirements.md`. |
| 4 | Контейнеры ↔ ADR; модель данных ↔ требования и агрегаты | API связан с ADR-0002/0003/0005, БД — с ADR-0004, статический сервер — с ADR-0006. Модель данных сопоставляется с агрегатами и матрицей `traceability.md`. | ADR-0002, 0004 и 0006 имеют статус предложения/подтверждения; версии и выбор стека необходимо согласовать с преподавателем и командой. |
| 5 | Ресурсы API ↔ требования | `resources.md` содержит операции для профиля, навыков/публикаций, обмена, подтверждения, отзывов и жалоб. | Перед сдачей пройти каждое FR в `requirements.md` и убедиться, что есть операция либо обоснованное отсутствие API. |

**Статус:** это предварительная сверка документов, а не протокол фактического командного ревью. После проверки командой замените формулировки в последнем столбце конкретными найденными расхождениями или отметкой «расхождений нет».

## Проверка синтаксиса Mermaid

Все файлы `*.mmd` должны проходить `@mermaid-js/mermaid-cli`. Локальная команда из корня репозитория:

```bash
find docs -name '*.mmd' -print0 | while IFS= read -r -d '' file; do
  echo "Проверка: $file"
  npx --yes @mermaid-js/mermaid-cli -i "$file" -o /tmp/mermaid-check.svg
done
```

Проверка синтаксиса не доказывает правильность смысла диаграммы. Смысловые ошибки выявляются пятью сверками и ревью.
