# Обзор архитектуры SkillSwap

## Назначение
SkillSwap помогает участникам находить взаимодополняющие навыки, согласовывать обмен и подтверждать проведение занятия. Это проектная архитектура, не описание уже реализованного приложения.

## Стиль
Модульный монолит с гексагональными границами (`ADR-0003`). Модули: Identity, Catalog, Exchange, Reputation, Moderation.

## Представления
| Диаграмма | Читатель | Назначение |
|---|---|---|
| [C4 Context](c4/context.mmd) | Заказчик/новый участник | Пользователи и внешние системы |
| [C4 Container](c4/container.mmd) | Разработчик/эксплуатация | Запускаемые части и хранилище |
| [Sequence](sequence/create-exchange.mmd) | Разработчик | Ключевой сценарий и отказы |
| [ER](data/model.mmd) | Разработчик БД | Сущности, ключи, кардинальности |

## Решения
`ADR-0001` — MADR (принято); `ADR-0002` — серверный стек ASP.NET Core 8 / C# 12 (предложено, сверить с кафедрой); `ADR-0003` — модульный монолит (принято); `ADR-0004` — PostgreSQL 16 (предложено); `ADR-0005` — серверная аутентификация и авторизация (концептуально принято); `ADR-0006` — отдельная раздача статических файлов через Nginx 1.26 (предложено к подтверждению). Версии технологий в C4 — проектные целевые версии, а не доказательство реализации.

## Качество: требование → тактика
| Требование | Тактика | Где |
|---|---|---|
| `NFR-01` | Индексы, пагинация, ограничение ответа | Catalog, БД |
| `NFR-02` | Health-check, проверка БД | API |
| `NFR-03` | Транзакции и ежедневный backup | БД/эксплуатация |
| `NFR-04` | Серверная проверка владельца/участника/модератора, хеширование паролей | Identity/API |
| `NFR-05` | Модули, интерфейсы портов, модульные тесты | Сервер |
| `NFR-06` | Два понятных сценария публикации и ясные статусы | Веб-клиент/API |

## Защищённость по замыслу
Ценные данные: email, профиль, публикации, история обменов, отзывы, жалобы. Угрозы: изменение чужих данных, подтверждение чужого обмена, доступ участника к модерации, утечка паролей. Меры: серверная аутентификация; проверка владельца/участника/роли; адаптивный хеш пароля с солью; серверная валидация; отсутствие секретов в сообщениях ошибок; HTTPS в рабочей среде. Многофакторная аутентификация и антифрод не входят в MVP.

## Осознанно не делаем
Микросервисы (не оправданы размером команды); видеосвязь и кошелёк (не нужны для гипотезы); Redis и брокер (нет подтверждённой потребности в MVP); отдельный поисковый движок (достаточно реляционного поиска); нативные приложения (веб-клиент покрывает сценарий).

## Открытые вопросы
Подтвердить серверный стек, СУБД и хранение токенов; согласовать окончательные приоритеты MVP.
