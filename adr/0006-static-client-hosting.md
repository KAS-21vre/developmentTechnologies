# ADR-0006: Раздавать веб-клиент отдельным сервером статических файлов

- **Статус:** Предложено к подтверждению
- **Дата:** 2026-11-20
- **Участники:** команда SkillSwap

## Контекст
Клиент SkillSwap реализуется на HTML, CSS и JavaScript без отдельного SPA-фреймворка. Для C4 важно показать самостоятельные запускаемые части: браузерный клиент, сервер, раздающий статические файлы, API и хранилище.

## Рассмотренные варианты
1. Раздавать файлы непосредственно из API — меньше процессов, но смешиваются обязанности доставки интерфейса и бизнес-API.
2. Использовать отдельный веб-сервер статических файлов — разделяет ответственность и позволяет независимо обслуживать клиентские файлы.

## Решение
Для проектной целевой схемы предложен Nginx 1.26 как сервер статических файлов. Версия и необходимость отдельного сервера должны быть подтверждены при выборе способа развёртывания; это не утверждение о существующей реализации.

## Последствия
**Плюсы:** отдельная ответственность за статические файлы, простая схема клиента и API.
**Минусы:** дополнительная конфигурация и ещё один процесс при развёртывании.
**Условие пересмотра:** если учебная инфраструктура или фактическое развёртывание проще обслуживает статические файлы средствами ASP.NET Core, отдельный Nginx можно убрать и пересмотреть C4.
