# ADR-0002: Согласовать серверный язык и каркас с требованиями кафедры
- **Статус:** Предложено к подтверждению · **Дата:** 2026-11-20 · **Участники:** команда SkillSwap

## Контекст
SkillSwap нужен REST API с серверной валидацией и проверкой прав. Исходные документы ЛР1 не закрепляют серверный язык. Методичка требует зафиксировать язык и каркас, заданные кафедрой; значит нельзя выдавать догадку за условие курса.
## Движущие факторы
- `C-04`: ограниченный семестр.
- `NFR-04`: серверная защита.
- `NFR-05`: тестируемость.
## Рассмотренные варианты
1. ASP.NET Core/C# — типизация, DI и встроенная инфраструктура; минус — использовать только если не противоречит кафедральному стеку.
2. Python/FastAPI — компактный API и быстрая разработка; минус — требует дисциплины типов и зависимостей.
3. Node.js/Express — единый язык с клиентом; минус — больше соглашений нужно определить самостоятельно.
## Решение
Предложение проекта — **ASP.NET Core 8 Web API / C# 12**, только если преподаватель не задал другой обязательный стек. Версии указаны как целевые для диаграммы, а не как подтверждённая среда реализации. До подтверждения стек остаётся «Предложено».
## Последствия
**Плюсы:** типизированный API, DI и встроенная валидация. **Минусы:** при несовпадении с требованиями курса решение придётся заменить.
**Что пересмотрит решение:** подтверждение кафедрального стека или несовместимость выбранной платформы.
