# Event Storming — SkillSwap

**Статус:** проектная расшифровка событий по требованиям ЛР2А. Для подтверждения фактической совместной сессии команда прикладывает фото доски Miro `event-storming.jpg`; в архиве фото не подменяется вымышленным свидетельством.

## 1. Поток команд и событий
| № | Команда | Событие | Правило / инициатор |
|---|---|---|---|
| 1 | Зарегистрироваться | `UserRegistered` | Email уникален |
| 2 | Заполнить профиль | `ProfileUpdated` | Владелец профиля |
| 3 | Добавить навык | `SkillAddedToProfile` | Категория: могу/хочу |
| 4 | Опубликовать предложение | `OfferPublished` | Активная публикация OFFER |
| 5 | Опубликовать запрос | `LearningRequestPublished` | Активная публикация REQUEST |
| 6 | Найти публикации | `SearchResultsShown` | Только активные публикации |
| 7 | Отправить предложение | `ExchangeProposed` | Нельзя отправить самому себе |
| 8 | Принять предложение | `ExchangeAccepted` | Получатель, пока статус PENDING |
| 9 | Отклонить предложение | `ExchangeRejected` | Получатель, пока статус PENDING |
| 10 | Предложить изменение условий | `TermsChangeProposed` | Любая сторона до согласования |
| 11 | Согласовать условия | `ExchangeTermsAgreed` | Обе стороны согласны с одной версией |
| 12 | Согласовать время и формат | `SessionScheduled` | После принятия условий |
| 13 | Отметить проведение | `SessionMarkedAsHeld` | Участник обмена |
| 14 | Подтвердить проведение | `CompletionConfirmed` | Подтверждение одной стороны |
| 15 | Подтвердить второй раз | `ExchangeCompleted` | Подтверждения обеих сторон |
| 16 | Оставить отзыв | `ReviewPublished` | Только после COMPLETED |
| 17 | Создать жалобу | `ReportSubmitted` | Авторизованный участник |
| 18 | Рассмотреть жалобу | `ReportResolved` | Только модератор |

## 2. Исключения и ветви
- Неверный профиль или публикация → ошибка валидации, состояние не меняется.
- Закрытая публикация → нельзя создать новый обмен.
- Отклик на собственную публикацию → запрет.
- Повторное решение по уже обработанному предложению → конфликт состояния.
- Согласование времени не завершает обмен.
- Первое подтверждение переводит обмен в `AWAITING_CONFIRMATION`; второе — в `COMPLETED`.
- Повторное подтверждение одного участника не заменяет подтверждение второго.
- Отзыв до завершения обмена запрещён.
- Решение по жалобе доступно только модератору.

## 3. Внешние системы
- Почтовый провайдер — возможен в следующем релизе; не обязательная зависимость MVP.
- Видеосервис — участники используют самостоятельно, платформа не управляет сессией.
- GitHub Actions — внешняя система разработки, проверяет репозиторий и документацию.

## 4. Открытые вопросы
1. Разрешить ли несколько активных публикаций одного участника по одному навыку?
2. Можно ли редактировать публикацию, если есть ожидающие предложения?
3. Как фиксировать отмену после согласования времени?
4. Может ли один обмен включать несколько занятий?

**Временное проектное допущение:** в MVP один обмен содержит одно занятие; отмена до завершения фиксируется отдельным статусом; изменение существенных условий требует повторного согласования.

## 5. Главное доменное правило
Обмен завершается только после подтверждения проведения занятия обеими сторонами. Это правило связано с `FR-23`, агрегатом `Exchange` и API `/confirm-completion`.
